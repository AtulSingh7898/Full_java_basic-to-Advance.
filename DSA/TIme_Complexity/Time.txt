Type Worst case of Time Complexity

O(1) — Constant Time Complexity -> it executes a fixed number of steps.
No matter how large the input size (n) is, the algorithm takes the same amount of time to execute.
It doesn’t depend on input

O(log n) — Logarithmic Time Complexity ->  The time increases logarithmically as the input size grows.w
This usually happens in algorithms that divide the problem in half each time, such as binary search.

O(n) — Linear Time Complexity->
Meaning:
The time grows directly proportional to the input size.
If input doubles, the time also roughly doubles.

O(n log n) — Linearithmic Time Complexity
Meaning:
Common in divide and conquer algorithms (like Merge Sort, Quick Sort).
The algorithm divides the data (log n) and does linear work (n) in each step.

O(n²), O(n³), etc. — Polynomial & qudratic Time Complexity ->
Meaning:
Occurs when there are nested loops.
The more nesting, the higher the power of n.

O(cⁿ) — Exponential Time Complexity ->
Meaning:
The time doubles (or multiplies by c) with each additional input element.
This often happens in recursion problems that explore all possibilities (like backtracking).

O(n!) — Factorial Time Complexity->
Meaning:
The time grows factorially — for every new input, it considers all possible permutations.
Very slow, used in problems like travelling salesman, permutation generation, etc.
